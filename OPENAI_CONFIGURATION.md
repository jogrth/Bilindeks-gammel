# OpenAI Configuration for AI Enrichment

## Overview

The enrichment system supports AI-powered content generation using OpenAI's API. When configured, the system will automatically generate high-quality, model-specific content including specifications, SEO content, and FAQ sections.

## Configuration

### Environment Variable

The system requires the `OPENAI_API_KEY` environment variable to be set:

```bash
OPENAI_API_KEY=sk-...your-api-key...
```

### For Local Development

Add to your `.env` file:

```env
OPENAI_API_KEY=sk-...your-api-key...
```

### For Supabase Edge Functions

Set the secret using the Supabase MCP tool or CLI:

```bash
# The secret will be automatically available to all edge functions
```

## Obtaining an API Key

1. Visit [OpenAI Platform](https://platform.openai.com/)
2. Sign in or create an account
3. Navigate to API Keys section
4. Create a new API key
5. Copy the key (it will only be shown once)

## How It Works

### With OpenAI Configured

When `OPENAI_API_KEY` is set:

- **Source**: `openai_generated`
- **Confidence**: 0.6 - 0.9+ (based on model recognition)
- **Content**: High-quality, model-specific Norwegian content
- **Specifications**: Real-world data when available
- **Trim Levels**: Actual trim variants if known

### Without OpenAI (Fallback Mode)

When `OPENAI_API_KEY` is **not** set:

- **Source**: `generic_fallback`
- **Confidence**: 0.3
- **Content**: Generic but usable Norwegian content
- **Specifications**: Conservative estimates (400km range, 500k NOK, etc.)
- **Trim Levels**: Empty (none generated)

### For Known Models

For the 10 curated models in the hardcoded dataset:

- **Source**: `known_dataset`
- **Confidence**: 1.0
- **Content**: High-quality curated content
- **Specifications**: Verified real-world data
- **Always Available**: No API key needed

## Enrichment Source Values

The system uses these source labels to track data origin:

| Source | Description |
|--------|-------------|
| `known_dataset` | Curated data from hardcoded EV_MODELS_DATA |
| `openai_generated` | Generated by OpenAI GPT-4 |
| `generic_fallback` | Generic templates (when OpenAI unavailable) |
| `manual` | Manually entered by admin |

## API Usage

The system uses the `gpt-4o-mini` model with:

- **Temperature**: 0.3 (for consistent, factual output)
- **Max Tokens**: 2500 (enough for full enrichment)
- **Cost**: ~$0.01 per model enriched

## Testing

To verify OpenAI integration:

1. Set the API key in your environment
2. Add a new model via the admin panel
3. Check the enrichment source in the database:

```sql
SELECT name, enrichment_source, enrichment_confidence, enrichment_notes
FROM models
WHERE name = 'Your Model';
```

Expected result:
- `enrichment_source`: `openai_generated`
- `enrichment_confidence`: 0.6 - 0.9
- `enrichment_notes`: "Generated by OpenAI"

## Fallback Behavior

The system gracefully handles missing API keys:

1. Attempts OpenAI enrichment
2. If API key missing or error occurs → fallback mode
3. Generates usable generic content
4. Marks source as `generic_fallback`
5. Sets confidence to 0.3
6. Adds note: "Generic fallback data - OpenAI API not available"

This ensures the system never fails completely and always provides some content.

## Upgrading from Fallback

When you add an OpenAI API key after using fallback mode:

1. New models will automatically use OpenAI
2. Existing models with `generic_fallback` can be re-enriched
3. No code changes needed - system detects key automatically

To re-enrich existing models:
- Delete and re-import the model, or
- Manually trigger enrichment via admin panel (if implemented)

## Cost Considerations

- Each model enrichment costs ~$0.01
- Batch importing 100 models: ~$1.00
- Re-enrichment not needed unless updating data
- Curated models (known_dataset) are free

## Security

- Store API key securely in environment variables
- Never commit API keys to version control
- Never expose keys in client-side code
- Rotate keys periodically
- Monitor API usage on OpenAI dashboard
